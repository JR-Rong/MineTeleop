# 会话日志导出

三端升级到包含本功能的同一版本后，在控制台登录，结束控制会话，点击顶部的
“导出会话日志”，选择会话并点击“收集三端日志”。收集完成后点击“保存 ZIP”。
桌面包弹出保存位置对话框；普通浏览器使用其下载设置。

只列出当前驾驶员参与、目前仍有车辆权限的已结束会话。云端目录按
`service_instance_id + session_id` 标识，避免重启后 session 编号重复。
目录在审计日志相邻的 `session-log-catalog` 中保留 7 天，页面显示最近 200 条。
旧版本产生且没有目录记录的会话不会凭编号猜测导出；云端崩溃时未正常结束的会话
不被伪装成完整的已结束会话。云端原始审计日志应继续保留用于这类事故排查。

## ZIP 内容

- `controller/control-browser-events.jsonl`：浏览器事件、原生控制发送与应答追踪。
- `controller/desktop-events.jsonl`：桌面进程生命周期及原生 stdout/stderr；普通浏览器模式可没有此文件。
- `vehicle/runtime.log`：车端运行和媒体诊断；启动器给每条持久化记录补充 UTC 时间，原始终端输出不变。
- `vehicle/vcu-can.jsonl`：CAN 收发、VCU 状态及本地安全停车诊断。
- `cloud/signaling-audit.jsonl`：该会话的云端状态、权限和控制转发审计。
- `manifest.json`：会话身份、UTC 时间窗、各端实际文件、字节数、脱敏和缺失原因。

匹配带 session ID 的记录，并限定在会话开始前 2 秒至结束后 2 秒的时间窗内。
没有 session ID 的 CAN/运行日志按主机 UTC 时间关联；这类记录在清单中计数，不能
当成精确的跨机时钟校准。云端审计仅导出明确属于此会话及服务实例的记录，防止
把同期其他驾驶员的审计混入。视频文件、系统 journal 和厂商终端专用噪声不属于
本功能的应用日志范围。

## 完整性与限制

导出会读取当前文件、数字轮转文件和云端小时归档。不会从遥测重造不存在的日志。
密码、令牌、认证头等字段会脱敏；不打包配置、设备令牌或 SSH 密钥。

车端需保持运行并在线，且目标车辆不能正在进行其他控制会话。车端由 supervisor
的独立线程通过既有 HTTPS 信令服务轮询和分块上传，不开新的监听端口，不需要 SSH。
每次传输最多 256 KiB 原始数据；CAN/媒体线程不执行导出磁盘读取。若开始新控制
会话，云端停止接收该导出的车端数据并标记缺失。

每个源文件最多导出 64 MiB、扫描最多 512 MiB，车端等待最多 180 秒；云端同时最多
保留两个导出任务，控制端下载完成后释放，未完成/未下载任务保留 10 分钟。
这些上限用于控制诊断工作量。离线、旧版本、权限错误、轮转丢失、未启用日志、
读错误、无时间戳或达到上限，都会在状态或 `manifest.json` 中明确体现。
`complete=false` 的 ZIP 仍可用于分析，但不代表完整会话证据。
日志内容本身若已报告丢帧或日志队列丢弃，也应结合这些事件分析，不能用 ZIP 的
文件校验成功替代运行时完整性结论。

关闭控制端会取消本地导出线程；新的驾驶员登录不能下载上一登录留下的 ZIP。
导出只读已有数据，不重启三端服务，不改变 CAN、驾驶限幅或审批设置。

## 回归入口

`mine-teleop-session-logs-tests` 覆盖实际 HTTP 三端收集与 ZIP 生成、跨驾驶员权限、
设备认证、路径穿越、轮转、脱敏、离线状态、目录重启、默认 bridge 根目录与 CCG2
配置。该测试同时加入 Linux/macOS CTest 和 Windows 原生打包测试。
