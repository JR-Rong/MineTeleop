# 现场反馈、发送期限与待发事件唤醒

## 变更范围

本次基于 PR24 的 `f328cb1` 整理此前现场使用的修复，并补充云端待发事件唤醒。
它是继续验证的版本，不代表连续 210 分钟长稳或实车安全已经验收。

- 车端以消息 `event` 区分原始状态与传输包装，避免原始 VCU 状态里的
  `status` 详情被误作包装、读取不到顶层 `control_status_seq`。
- 补充传输拒绝原因、真实反馈应用结果、WSS 写调用和 DataChannel 回执路径诊断。
  浏览器待执行命令仍只保留最新状态；执行回执用有界队列保留，避免后续成功
  覆盖中间拒绝。它不改变重放、过期、鉴权或实际应用的判定。
- 诊断输出使用有界生产者队列，控制路径不等待日志消费者；丢弃计数保留。
  车端退出先关闭控制适配器，再完成媒体和日志清理。
- 发送前重新核对输入租约和输入版本。JSON 序列化或封帧已经耗尽期限、且尚未
  执行任何写入时，只丢弃该未发送快照；不得记为发送或应用成功，也不重放旧输入。
  真正开始写入后的超时仍按原逻辑退休连接。
- WebRTC 的固定视频 codec preferences、NACK/RTX 和控制 DataChannel 在生成
  首个 offer 前配置，避免一条相机无帧阻止全部轨道协商；H.264 caps 明确
  `packetization-mode=1`。相机故障仍服从原关键画面门禁。
- 桌面明确使用默认物理接口可用候选策略，新增脱敏 ICE 地址族与呈现帧年龄诊断。
  候选存在或 STUN 成功不代表已经选中直连。
- 按用户明确要求，两端校时不确定度默认值改为 **100 ms**，显式更严格的配置
  仍生效。该值不是控制命令年龄、视频延迟或 socket 写入预算。

## 事件唤醒的行为

原先云端线程在检查待发消息后，进入 `receive_json(10 ms)` 等待网络输入。
其他线程放入新命令不会唤醒该 socket 等待，因此健康网络下仍可能额外等待一个
轮询周期。普通信令的对应空闲等待为 50 ms。

现在每个有下行任务的连接持有独立的 `SocketWakeup`。消息入队、有效新反馈、
控制租约更新或会话结束后，通知对应会话和接收方的连接。网络 socket 与本地
通知端点在同一个 `poll` / `WSAPoll` 中等待，无须增加发送线程。

通知采用仅绑定 loopback、互相连接的非阻塞 UDP 端点。多次通知合并为一个待取
信号，数据仍保存在原队列或最新状态槽中，不将通知数量当作命令数量。通知先于
等待也会保留；通知与网络帧同时到达时先处理网络帧，保留通知供随后检查待发状态。
弱引用订阅随连接和会话清理，不在已关闭连接上复用通知描述符。

原有 10/50 ms 定时检查保留，继续核验身份、过期和重发条件；本地通知失败有
`signaling_wakeup_failed` 诊断并回落到原有有界等待。新消息不需要等待定时检查。
部分网络帧的既有组帧期限不在本次修改范围内。

车端的异步 WSS 反馈也使用同一通知机制：其他线程发布状态或执行结果时，唤醒
唯一的网络所有者，不再依赖最长 100 ms 的接收等待自然结束。原 WSS 命令处理
流程中的直接执行反馈仍在原处发送，不为它增加额外通知。退出、取消和媒体故障
同样通知接收线程；通知失败计数进入最终诊断，原 100 ms 超时继续作为回退。

`WebSocketClient` 可在 socket 可读与本地通知之间等待。通知返回独立的
`Notified` 状态，既不是网络消息也不是空闲超时；已收到的部分头部和负载保留，
下一次接收继续组帧。各条连接始终由一个线程调用 CURL，不增加并行收发线程。
这项改动保留 50 ms 独立看门狗、20 ms 写入期限和全部控制门禁。

驾驶端等待下一次发送期间，新增 ACK socket 可读唤醒，并将急停/停止通知放在
同一个有界等待中。只在取得连接锁时获取该连接缓存的只读等待句柄，随后释放锁
再等待；等待句柄保留原 socket 的独立描述符，不读取 CURL，也不消费网络数据。
真正接收仍由原所有者核验当前会话后执行，连接关闭会中断旧句柄，描述符重用不会
将旧等待指向新连接。不能取得接收锁时退回原定时等待，避免忙循环。
Windows CI 发现，仅 shutdown 复制的 socket 不足以唤醒已阻塞的 `WSAPoll`；
等待句柄因此另持有退休通知。所有者释放 CURL 前先发布退休，唤醒等待后仍须
重新核验连接，退休通知不算网络反馈。相同回归在 Windows x64/arm64 上执行。

TLS 库内部可能已有缓存数据，因此保留最多 20 ms 的有界接收复查；20 Hz 普通
发送节拍也不变。可读或本地通知本身不算 ACK，不延长 200 ms ACK 新鲜度、
500 ms 无进展或恢复期限。新增状态计数区分网络可读唤醒、等待失败和通知失败。

浏览器 DataChannel 反馈新增到达通知。普通执行结果仍用 64 项 FIFO，状态仍按
类型保留最新；新数据到达即安排一次合并调度。每条桥接路径只允许一个 HTTP
请求在途，成功后继续处理剩余反馈，普通控制与急停路径保持独立。待执行通知
携带当前会话/代次/页面/媒体协商的有效性检查，退休后不会唤醒替代会话。

请求失败后至少等待原 25 ms 周期再重试，期间新反馈不会引起忙循环。通知不含
命令数据；命令仍由原生层产生，已有序号、有效期和只发送一次的检查保持不变。
原生层尚无向页面推送待发命令的接口，因此保留 25 ms 周期获取新命令，不能将
此次反馈加速描述为整个 DataChannel 桥接已经消除轮询。

`20 ms` 是从 `send_json` 开始、覆盖序列化/封帧/TLS 写入的单次本地预算。
本次不增加这个预算，不改变 20 Hz 普通发送节拍，也不取消无包时的安全检查。
中断的底层 poll 重试继续使用原截止点，不能重新获得完整等待时间。

## 验证与界限

新增可移植原生回归验证通知提前到达、重复通知合并、阻塞等待唤醒及通知消费后
不形成空转积压。原有部分写入、完整但超期写入、取消、连接退休和描述符生命周期
测试继续运行。完整控制回归覆盖会话隔离、反馈、重复消息、租约与安全恢复。

车端补充回归使用真实 loopback TLS/WSS，覆盖空闲接收被通知中断、普通头部/
扩展头部/负载三个位置的部分帧保留、接收半包时仍能发送反馈、重复通知合并及
消费通知后的正常超时。提取实际车端发布方法的测试还核对 WSS 状态通知、异步
结果通知，以及直接 WSS 结果和 DC 状态不会唤醒无关路径。

驾驶端新增真实 TLS 回归覆盖：网络到达唤醒后由原所有者读取、本地通知不冒充
网络进展、连接退休中断旧等待，以及等待句柄不跟随复用的描述符。原生 ACK 窗口
满载后的急停场景还要求实际运行时观察到可读事件，且没有通知或等待错误。

浏览器回归使用可控制的调度和 HTTP 完成顺序，覆盖突发反馈合并、FIFO 中间
拒绝保留、状态替换、在途新反馈、错误退避、过期会话通知、异常响应不自旋和
定时任务与通知竞争；还提取实际页面初始化代码，验证普通及急停反馈均能在
不触发定时任务的情况下上报，同时保留周期获取新命令。

本机实际 `SignalingService` 的 32 次 loopback 转发对照：

| 版本 | P50 | P95 | 最大值 |
| --- | ---: | ---: | ---: |
| 10 ms 定时轮询 | 5.426 ms | 10.401 ms | 11.138 ms |
| 同样期限加待发通知 | 0.479 ms | 0.724 ms | 0.809 ms |

这是本机回环样本，不能外推公网尾延迟或 Windows 现场表现。跨平台构建和回归
以对应提交的 CI 为准，不能以 macOS 编译代替 Windows 或 Ubuntu 验证。

驾驶端另做四轮各 64 条 ACK 的 A/B/B/A 回环对照：使用相同的当前运行库，仅将
发送线程循环替换为原 20 ms 轮询逻辑作为基线。真实 `DriverConsoleRuntime`
接收测试云端响应；不包含车辆应用、CAN、公网或 TLS，毫秒级单调时钟测量从
云端响应发出到驾驶端确认的时间。两轮基线 P95 均为 29 ms，唤醒版本均为
1 ms；最大值分别为 42/50 ms 和 20/23 ms。尾延迟仍存在，不作为硬实时保证。

## 尚未通过的现场项目

2026-10-19 的最近一轮仅使用隔离 non-root mock 和 ch6/ch7 真实相机，W、WA、A、
AS、S、DS、D、WD 每组按住 15 秒并回零 1 秒。有效窗口约 **547.2 秒**，完成四个
完整组合循环后失败，不能拼接成连续 210 分钟。

触发命令的单次 `curl_easy_send` 墙钟时间为 **22441 us**，线程 CPU 为 **154 us**，
`poll_calls=0`。库报告全部字节写出，云端确实转发且收到对应车端反馈；本地写入
期限仍被越过并触发控制链路保护。当前证据不能区分该调用中的 TLS 等待与线程
调度停顿，也不能宣称云端事件唤醒已经解决它。

本轮控制走 WSS，视频走 TURN relay/relay UDP；IPv6 探针仍有单向不可达，
尚未完成 P2P 路径验收。视频短窗采样为 29–31 FPS，ch7 记录一次 0.192 秒冻结，
应保留该异常而不能报告零冻结。

本轮停止后现场主动重启车端，远端临时目录被清空。已有驾驶端采样和云端逐序号
记录保留，但完整车端应用/资源日志及正常退出标记没有完成归档，相关结果为
无法判定。下一次测试必须在运行中持续保存远端日志，不能依赖结束时一次性复制。

重新验收仍需同一版本、同一会话连续 12600 秒，覆盖三段 70 分钟；分别记录视频
和控制路径、真实应用和反馈、停车原因、视频更新/冻结及资源。孤立丢包如实统计，
不计为应用成功；本次不放宽其他现有门限，不接触 CAN 或执行真实车辆动作。
