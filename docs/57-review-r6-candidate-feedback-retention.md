# 审查 R6：确认前状态有界保留

`review-r6-before.log` 保留失败：真实 MAC 的候选 epoch 拒绝事件先于
选择结果到达，被 Sender 消费；同一选择结果随后可正常确认，但该
一次性事件已经没有重传来源。

修复保持原发送顺序，无需假设无序 DC 先到结果。native 在 MAC/身份
校验后，仅为当前候选反馈戳保留最多四类、每类最新一个状态。暂存不
更新结果健康度、全局状态序号或 UI。更换选择/epoch即清除旧候选。

精确选择结果确认后，原队列先重新核对scope/floor，再按publication
seq排序；经同一MAC与状态门禁释放一次。不能靠暂存刷新原CAN证据时间，
不能让旧epoch巨大seq挤走当前epoch状态，也不改既有跨批次全局水位语义。

生产类与专门候选测试 **2/2通过**；真实localhost集成增加一次性
签名拒绝通知先于延迟选择结果的故障注入，确认后只交付一次。
日志 `review-r6-after.log`、`review-r6-loopback.log`。

实验仍默认关闭，期限不变；没有新增网络、线程、普通命令双发或现场部署。
