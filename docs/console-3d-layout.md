# 控制端三列布局与可替换自车模型

本次基于 `b5f8eb0ae56e259355f7a5cbd0f3ae81d349b533` 的 main 实现 A/B/C/E：布局、轻量 3D、自车模型配置与视角交互、验证及离线资源交付。相机 ID 绑定与少路数布局已补充，环视拼接和障碍物数据接入留待后续。

## 布局与分辨率

- 顶部合并实测车速、实际/指令挡位、转向/目标车速比例/刹车指令，以及八路轮端扭矩、转速、制动压力、模式和四路转向角/模式。
- 宽屏主体以相机 60、3D 26、操作区 14 分配可用宽度；操作区最小 220 px、最大 300 px，因此受限屏幕不强行保持百分比。
- 相机按车端声明的 ID 固定排序，支持 1～8 路自适应布局；不足六路时不补虚构视频。环视按钮禁用并标明待接入，不创建虚假的拼接结果。
- 右栏依次为键盘状态、车辆状态、VCU 握手和运行监控；监控内部滚动。高度不足时右栏整体滚动，前两列保持可见。
- 宽度 ≤1100 px 时，相机和 3D 保留两列，操作区移到下方；≤720 px 时顺序变为相机、3D、操作区，页面纵向滚动。
- 视频使用 `object-fit: contain`，保持原始比例；3D 用 ResizeObserver 更新画布和相机取景，限制设备像素比为 1.5、渲染上限约 30 FPS，隐藏页面暂停绘制。自动视角过渡中改变窗口尺寸时，按新取景距离缩放过渡起点和终点并保留进度，避免停在半途角度。

## 视角行为

鼠标左键拖动绕自车旋转，滚轮缩放，禁止平移到远离车辆的位置或翻到地面以下。不注册键盘控制监听器，方向键/WASD/Space/B/E 继续由现有驾驶逻辑处理。

自动视角使用实测速度的绝对值：停车为车头向上的垂直俯视，行驶和倒车均为固定在车尾上方的斜视。默认 ≤0.05 m/s 视为静止，≥0.08 m/s 视为运动，中间区间保持原模式，连续满足 300 ms 后切换，动画约 500 ms。

拖动/缩放期间暂停自动；最后一次操作结束 5 秒后恢复，也可点击“恢复自动”。支持 CAN 的遥测必须同时满足 `speed_valid`、`feedback_fresh`；遥测缺失、非数值或超过 500 ms 时保持当前视角，不把断流当作停车。无 CAN 完整反馈的适配器使用遥测中的 `speed_mps`。

## 配置与模型替换

控制端 YAML 的 `ui` 段：

```yaml
ui:
  default_layout: grid_6
  scene_enabled: true
  scene_manifest: models/haul-truck/model.json
  # assets_root: ../assets
```

`assets_root` 相对 YAML 所在目录解析。默认先找包内 `../assets`，源码运行时找 `../cpp/web/assets`。模型 manifest 相对于 assets 根目录；更换模型只需放入资源、调整 manifest 和配置并重启控制端，无需修改或编译 C++。

例如 `assets/models/new-truck/model.json`：

```json
{
  "name": "自车",
  "file": "truck.obj",
  "material": "truck.mtl",
  "scale": 1,
  "rotation_deg": [0, 0, 0],
  "offset_m": [0, 0, 0],
  "camera": {
    "stopSpeed": 0.05,
    "moveSpeed": 0.08,
    "settleMs": 300,
    "resumeMs": 5000,
    "staleMs": 500
  }
}
```

支持 GLB/glTF、FBX、OBJ；OBJ 的 MTL 是可选项。文件和纹理路径按 manifest/模型所在目录解析，所有外部文件必须在同源 `/assets/` 内（允许模型内嵌 data/blob 纹理），运行时不依赖 CDN。默认普通 PNG/JPEG/WebP 纹理；未配置 Draco/KTX2 解码器，不承诺支持这些压缩扩展。任意 FBX 的高级材质/动画不保证与制作软件等效，本阶段只显示静态模型。

模型坐标约定为 Y 向上、车头朝 +Z；偏差通过 `rotation_deg` 校正。`scale` 转换模型单位，`offset_m` 设置位置，取景按模型边界自动居中。当前提供的 FBX 单位元数据按厘米处理，设 `scale: 0.01`，但实际外形尺寸尚未标定；网格仅作视觉参考，不能用于障碍物距离验收。

静态服务只允许资源扩展名，拒绝目录跳转、资源目录外的符号链接和超过 128 MiB 的单个文件。资源缺失或 WebGL 不可用时在 3D 区显示错误；驾驶控制不依赖 3D 初始化结果。

## 默认模型与前端构建

使用 Three.js 0.186.0，按需加载 FBX/OBJ/MTL loader。编译后的 JS/CSS 和模型保存在 `cpp/web/assets`，三个平台打包脚本都拷贝该目录。终端用户运行包不需要 Node/npm。

默认矿车由提供的 `carcz(1).fbx` 离线生成 GLB，原件未修改：

- 原件 90,938,620 bytes，989,234 三角面；默认 GLB 14,551,632 bytes，178,062 三角面。
- 原件 SHA-256、边界和转换参数见 `cpp/web/assets/models/haul-truck/haul-truck.glb.provenance.json`。
- 转换保留静态几何和基础/法线纹理，基础纹理最长边 2048、法线 1024；不用于通用 FBX 无损转换。新模型可直接用 FBX loader，无需经过此脚本。

修改前端源码后（开发工具使用 Node 22.12+）：

```sh
cd cpp/web
npm ci
npm test
npm run build
# 可选：对适用的单材质静态矿车重新生成展示模型
node prepare-model.mjs /absolute/path/source.fbx assets/models/haul-truck/haul-truck.glb
```

`build.mjs` 每次清理生成的 chunks 后重建，保留模型目录；`package-lock.json` 固定依赖。`THIRD-PARTY-LICENSES.txt` 随资源交付。资源改动应与源码一起提交。

## 本地 UI 验收夹具

先启动实际控制端，再运行隔离夹具（Node 22.12+，仓库根目录）：

```sh
build-native/mine-teleop-control --config configs/driver-console.dev.yaml --port 4388 --no-open-browser
node scripts/test/preview_console_scene.mjs http://127.0.0.1:4388 4389 /absolute/path/carcz.fbx
```

打开 `http://127.0.0.1:4389/`，显示模拟六路画面和 CAN；按钮可切换停车、行驶、倒车和停止遥测。`/?model=obj` 验证 OBJ/MTL，`/?model=fbx` 验证命令行给定的原始 FBX。夹具只读代理资源，拦截其余 API 并禁用真实操作按钮，不创建车辆会话。模拟画面不是六路 WebRTC 解码或实车性能证据。

检查 1920×1080、1280×720、1024×768、390×844 的布局；验证自动切换、手动拖动、5 秒恢复、立即恢复、遥测失效保持视角，确认缩放/拖动不改变驾驶指令。

## 相机身份、排序与缺帧显示

车端 `cameras[].id` 采用下列约定，区分大小写；同一车辆内 ID 必须非空且唯一。
无需额外 `role` 字段，ID 不改变实际设备路径或关键相机安全策略。

| ID | 网页名称 | 平铺顺序 |
| --- | --- | --- |
| `drive_front` | 前视驾驶 | 1 |
| `drive_rear` | 后视驾驶 | 2 |
| `drive_left` | 左视驾驶 | 3 |
| `drive_right` | 右视驾驶 | 4 |
| `fish_front` | 前鱼眼 | 5 |
| `fish_rear` | 后鱼眼 | 6 |
| `fish_left` | 左鱼眼 | 7 |
| `fish_right` | 右鱼眼 | 8 |

前后驾驶视角优先。只渲染 offer 中声明的启用相机；不按视频到达顺序排布。
既有自定义 ID 仍可使用，显示原 ID，并按 ID 字符顺序排在标准相机后面。
原始 offer 列表仍用于 SDP MID 与相机绑定，显示排序不会改变视频身份映射。

- 1 路铺满相机区域；2 路在区域宽高比小于 16:9 时上下排，否则左右排。
- 3 路第一视角占整行，另外两路并排；4 路为两列两行。
- 5～6 路为两列三行；7～8 路为两列四行，奇数路保留末尾空位。
- 启用但未收到视频的相机预先占位。连续约 3 秒没有新显示帧会覆盖旧画面并提示，检查周期为 500 ms。
- 轨道 muted/ended 或媒体连接断开时提示中断，保留原位置；恢复新帧后自动显示。
- 重新协商按新 offer 重建清单，退出会话清空占位；此显示逻辑不改变车端关键相机锁止或驾驶准入。

四个 `fish_*` 专供后续环视标定和拼接，`drive_*` 为独立视角。当前没有拼接实现，
即使四鱼眼齐全也不会启用环视按钮。标定需按车辆和鱼眼 ID 绑定；更换镜头或安装位置后更新标定。
配置设备对应方向需要现场确认，不能仅凭采集卡通道号猜测方向。
