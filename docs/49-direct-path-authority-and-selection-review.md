# PR24 直连后续设计审查：授权、急停、独立反馈与持续选路

本文件是 `6db3cbb` 默认关闭实验之后的**设计提案**，没有实现或启用下述新增行为，没有部署、网络变更或安全门限修改。现有实现和测试边界见 [48-experimental-native-dc-control.md](48-experimental-native-dc-control.md)。

给用户的建议可以只说：**建议云短暂不可达时，让当前唯一驾驶员在短授权剩余时间内继续；只要画面、操作、车端结果或授权任一不再满足条件，就停车。不能让直连包自行续权，也不能拿现有五分钟登录式 token 当容忍期。云恢复后若已经停车，仍须松开重按。**

用户只需决定一个产品取舍：**云暂时不可达，但仍看得见车、车仍及时收到操作并回报时，是否允许当前驾驶员继续到短授权自然到期？** 推荐“允许”。租约、检测、采样和切换的具体毫秒数由工程测量与安全验收确定，不交给用户逐项选参数；没有通过这些验收前继续保持实验关闭。

## 先分清当前事实

- `SignalingServerConfig::control_token_ttl_ms` 默认五分钟，续租安排在剩余有效期的三分之一处；native 租约线程目前每 250ms 检查一次。这套配置不是短直连授权协议，也不具备所需的撤权上界。
- dev 配置的 command max-gap=200ms、degraded watchdog=300ms、control watchdog=800ms，都是已有控制保护。持续收到新鲜 DC 操作时 watchdog 可以一直不触发；**“等原 watchdog”不能单独限制云静默失联的时长**。这些数值不能倒推成新的云断线阈值，也不是实际车辆已停车的时间保证。
- 现有 native 续租错误会进入 failure，页面信令错误会结束 realtime session，车端媒体信令错误会终止本次媒体运行；页面还把 `signaling_available=false` 与时钟可信性合并。模式 A 必须显式、局部地拆开这些耦合，不能只删除一个 `connected` 判断就声称支持健康 P2P 继续。
- 在消息不能到达的网络分区中，无法同时保证“立即远程撤权”和“健康直连始终继续”。可以保证的是已约定的最坏撤权界、始终单一车端权威，以及更早发生的独立安全保护。

## 两种明确语义

| 项目 | A：保持当前唯一短租约，直到最早安全边界（推荐） | B：确认云失联即撤回运动 |
| --- | --- | --- |
| 暂时云 I/O 失败，DC 操作、结果、视频、输入和时钟仍健康 | 标记“云连接异常，当前授权倒计时”；仅当前驾驶员、当前车、当前权威代次继续。不会重新授权、延长 deadline 或绕过任何既有门禁 | 本地一确认失败就撤销旧输入、请求制动；即使 DC 很快也不继续运动 |
| 静默黑洞、socket 仍显示 connected | 仅活到最后已由车端接受的短租约截止；DC 包、TCP keepalive、旧 ACK 都不能推迟它 | 由认证的 authority 请求/响应超时发现，随后停车。必须明确这个检测上界；“即停”不是瞬间知道网络已断 |
| 真正撤权、认证拒绝、会话被替换 | 两端收到就立即封存旧权威并停车，没有“宽限” | 相同 |
| 最早结束条件 | 短租约到期，或已有输入/视频/结果/时钟/车端安全条件先失败，或明确撤权；谁先发生用谁 | 检测到云不可用，或任一原安全条件先失败，或明确撤权；谁先发生用谁 |
| 云在租约内恢复，所有原安全条件始终通过 | 同一短租约可正常更新，不因一次短云抖动强制重新登录/松开重按；UI 清除云异常提示 | 已停车则依原恢复规则重新取得新鲜授权与健康条件，松开重按；不恢复旧按键 |
| 已到期/已停车后恢复 | 不复活旧 lease/epoch 或旧输入；新有效授权、neutral 和原恢复门禁都通过才可重新驾驶 | 相同 |
| 体验代价 | 减少“画面和操作都好、只是云闪断”造成的停车；代价是远程撤权无法到达时存在明确、短且有界的生效延迟 | 远程控制面的故障更快转为停车，但云 RTT/短抖动/服务重启会打断健康 P2P，恢复操作更频繁 |

A 中“保持”仅指**已经签发并由车端接受的当前短租约剩余期**。不是从断线时重新计算一个完整期限，不是延长 300/800ms watchdog，不是放宽 command age，更不是五分钟离线驾驶。B 也不能仅检查 connected 标志；否则名义上严格、实际无限期不发现黑洞。

## 推荐的最小授权协议

采用两种模式共用的一个车端权威记录，云失联策略是其上一个模式位。普通 path epoch、feedback epoch 与 authority epoch 分开；更换路径不续权，更换回程不换驾驶员。

1. **权威由云授予、车端落地。** 租约绑定 cloud instance/leader term、vehicle boot nonce、vehicle/driver/session、authority epoch、lease seq、绝对截止、车端本次 renewal nonce。车端一次只接受一个 current authority epoch；same-epoch 续租只能增加 lease seq，不能改变驾驶员或车辆。native 只能携带租约身份，不能自行签发或延长。
2. **复用已有认证云→车信道。** 最小实现直接在该信道下发 grant/renew/revoke，车端保留不可被 DC 改写的已接受记录，并回 `lease_accepted`。native 的 DC 命令引用该记录。若将来需要经 native 转送租约，才增加云签名并由车验证；不能用阶段 2 中 native 也持有的会话 MAC key 签授权，否则 native 能伪造续权。既有 command/result MAC 继续只证明消息来源和内容完整。
3. **到期由本机单调时钟执行。** 将云绝对截止结合可信时间区间保守换算为 monotonic deadline，扣除时钟不确定度；同时不得晚于本次 renewal nonce 发出时刻加允许租期。收到晚 grant、重复 grant、旧 lease seq 不能按“收到时间+完整 TTL”延长。时钟不再可信或 suspend/重启破坏该映射，就按原保护停车。native 使用不晚于车端的保守截止；车端独立执行，不能依赖页面轮询。
4. **短租约不是原 token。** 独立 `direct_authority_lease` 上限 L，只能更短地限制普通控制，不能延长任何既有安全门限。复用“约三分之一处续期”的形状，但必须用独立、准时的任务，不能直接复用目前 250ms 检查循环。由已有云事务携带认证的单调进展即可，不新造 50ms 心跳流。
5. **明确数值验收关系。** 设 R 为续期开始时刻，D 为一次 authority 事务截止，U 为时钟不确定度，J 为本机最坏调度余量；必须有 `R + D + U + J < L`。L 加本机执行余量不得超过工程审查的“最晚撤回运动”预算 B。D 来自同部署拓扑的认证事务延迟与失败注入，不能来自 STUN/ICE RTT。若现有网络与 B 无法同时满足，不扩大 B 或原 watchdog，维持关闭或采用 B 模式。**本文件不把 200/300/800ms 或五分钟默认套成 L/D/B，也不声称这些新预算已批准。** 物理停车时间还需独立 CAN/执行机构证据。
6. **分区期间不续权、不换人。** A 模式只允许当前已有授权的操作；禁止登录式接管、权限提升、离线 VCU 重新 connect、参数增益修改和新媒体会话。当前安全状态反馈、制动、急停、VCU disconnect 继续允许。云可达但车端未接受续租，native 不能仅凭云 HTTP 成功认为已延长。
7. **撤销不能和重授重叠。** 云收到撤权先停止续租，记录该车所有已签发租约的最晚截止；到达车端则原子封存旧 epoch、制动并回带 nonce 的 revoke ACK。云不得在“旧权威已封存且满足原安全交接条件”或“最晚租约已保守到期并重新验证车端安全交接条件”之前激活新驾驶员。仅收到云端注销请求、软件 revoke ACK 或超时过去，都不能代替停车/CAN/VCU 条件。车离线时保持不可接管，不能为 UI 流畅生成第二个有效所有者。
8. **处理迟到和重启。** revoke 是同一 epoch 的终态，旧 renew 即使更晚到也不能复活；新会话必须新 authority epoch。云重启/领导权变化先对账车端并恢复持久的最晚 grant/epoch，无法证明就禁止发新权；车重启产生新 boot nonce、处于停车态，旧 grant 全部失效。旧实例和新实例并行时，车端同一锁下的 epoch/term fence 是最后防线，不能靠两个内存 session 表各自“排他”。
9. **失败分类可审查。** 仅暂时连接/超时错误且 A 的有效短租约+全部原安全条件成立，才可保留现有 PC/控制服务；401/403/撤权/会话冲突立即停止。time-sync 失效仍执行原保护，不能把“云暂时不可用”解释成允许不可信时间。到期动作由独立安全执行线程触发，普通 DC 包不能刷新 authority deadline 或掩盖这次停车。

模式 B 共用上述 fence/lease，另在认证云事务首次确定失败、连接关闭或无新鲜认证进展的截止触发停车；D 必须单独验证。在无 D/短 lease 实现前，两种语义都不能作为上线承诺。需要用户决定的是采用 A 还是 B；上述防双重授权、MAC 边界、时钟和恢复规则由工程负责，不是可关闭的选项。

## 急停：最快健康路径优先，并做一次有界冗余

建议为急停引入明确版本化的 stop-only 消息，沿用 native 唯一全局命令 seq 和 latch；`emergency_id=(authority_epoch, command_seq, body_digest)`，消息签名不绑定 ordinary path epoch。它只能锁存停车，不能设置油门、解除急停、授权、变更参数或续租。

- native 按下急停先原子锁存、撤回运动并发布急停，再做可能阻塞的 socket 写。当前最快健康的已授权路径为主，同时向另一条已存在、已授权的可用 DC/WSS 路径各发送同一份急停一次。只有这个 stop-only 事件允许有界冗余；普通驾驶仍单路。持续按住后的新序号和重试沿原保守急停策略，不能建立无界双路积压。
- 车端校验同一车辆/当前权威/签名/源时间，先执行 latch 再发结果。允许越过 ordinary path 正在选择/退休的栅栏；不能越过身份或已被新驾驶员替代的 authority epoch。当前权威刚到期但尚未替换时，只允许该已绑定身份的 stop-only 动作，不允许普通运动；车端到期保护本就应已停车。
- 第一次有效急停进入共同服务；重复先匹配有界已处理摘要，回原结果但不再次 apply、不刷新 watchdog、不延长租约。native 锁存后不再生成普通运动包，避免更高 ordinary seq 覆盖急停。旧 reset/authority epoch 的急停重放不能影响新会话；复位始终走既有本地确认，网络 stop 消息没有 reset 能力。
- DC 与 WSS 并发分派不能拿着同一阻塞发送锁顺序等待；只共享生成 seq/latch 的短临界区和车端执行锁。复用既有信道，不能声称能越过 TCP/SCTP 已经排队的字节；背压、HOL 阻塞和本机 25ms courier 调度都计入按下→车端锁存时延。不要凭媒体 RTT选择或确认急停。
- 车辆急停软件结果可沿两个可用回程有界回报，不等普通 feedback 选路完成。UI 分别显示“已请求”“车端已锁存”“物理状态已确认”；双路都无结果时只能显示未确认，不能宣称已停。

这需要独立协议审查；阶段 2 仍仅 WSS 急停，不能靠把现有 stamped DC 普通包复制到 WSS 实现此设计。

## 反馈独立选路

控制结果和四类状态各保留原语义，新增独立 `feedback_epoch` 与 `(command_path, feedback_path)` 记录。回程可以是 WSS 命令→DC 结果，也可以是 DC 命令→WSS 结果；反馈选择不改变控制权或 ordinary path epoch。

1. 通过当前已授权命令路径捎带认证 `feedback_select(from_epoch,next_epoch,path,media_attempt)`；车端在原锁内提交回程边界并返回确认。它不是新的 actuation 命令，不修改 motion/gear/watchdog。新回程未验证时不抢先声明成功。
2. 反馈比较使用相同车端事件/序号。低频、限额的 return probe 在车端一次产生，再各向可用回程发同一 nonce；native 在同一单调时钟看两份到达的差值，以相同去程消去 forward 抖动。绝对“生成→接收”只在双方可信时间及不确定度足够时报告，否则保持未知；不能把混合 RTT 冒称一向反馈延迟。探测不执行控制、不续任何 watchdog/授权。
3. 主反馈平时只走选中一路；备用仅有界探测。切换时允许一个确认/快照批次的重叠，按相同结果身份去重，不建立持续双路遥测架构。最终资格必须由真实已发送命令的真实车辆结果确认，probe 快不能代替软件接受/安全健康。
4. 切换屏障给出 status floor。新回程发送四类最新快照并分配新的递增 status seq，按生成顺序交同一 reducer；旧 feedback epoch 在更新 UI watermark/健康样本前被拒绝。旧包即使 seq 很高也不能压住新会话/新回程；未匹配 seq/intent 的结果不作累计接受确认。
5. 回程切换无缺口且原健康持续时，不因回程标签改变强制驾驶员重新按键；真实反馈不健康仍照原恢复/制动。急停回报不等待该择优器。时钟、CAN freshness 和 profile/VCU 门禁不因另一个回程变快而放宽。

## 持续最低健康延迟重排

只比较**当前可选择且已健康验证**的路径。单 PC 的实际 DC 路径可能是 P2P/TURN；浏览器不能靠改业务分数任意提名另一条 ICE pair，因此候选是“本次实际 DC 路径”和“云 WSS”，不能假装同时可选 P2P、TURN/UDP、TURN/TCP。视频仍由 ICE all 连通；按 capture→presentation 强制切媒体路径需要额外能力和单独 A/B 证据，当前不承诺。

- 当前路径持续采集精确 command seq/intent→车辆结果；备用只做认证、非执行、带 nonce 的有界 path probe，经过相同真实传输/车辆处理队列。probe handler 必须独立于 ControlCommand，不能刷新控制 watchdog、触发 VCU 或赋予驾驶资格。
- 候选记录 session/authority/普通路径 epoch、media attempt、actual ICE path、feedback epoch；进展必须来自新结果。ICE restart、换回程、换 owner 后重建相应样本 cohort。拒绝响应、云入口 ACK、媒体 RTT、静态重复样本均不计健康资格。
- 健康资格先看丢失、尾延迟和原保护，性能排序建议同 cohort 的真实结果 p95 优先、median 辅助，而不是仅靠三包均值；样本不足保持“待验证”。窗口长度/样本下限与稳定参数一起通过故障注入定案，不能为凑 p95 放宽安全 freshness，也不能用较快平均值掩盖偶发秒级停顿。
- 反馈与去程一次只优化一个轴：先比较回程，固定回程后比较控制去程；否则两个选择器互相改变混合 RTT，可能反复翻转。不能从 `DC+快回程` 与 `WSS+慢回程` 推断单一去程孰快。
- 复用阶段 1 的改善绝对值/比例、新样本稳定窗、最小驻留机制；配置由同拓扑延迟噪声和切换成本测定，fixture 的 5ms/10%/100ms/300ms 不是默认。工程默认策略为：健康路径的性能切换排到下一次自然 neutral，再经过 epoch 栅栏和真实 neutral 结果验证；当前路径硬失效则立即撤回运动并验证回退，不等驻留。
- 更快备用只代表“值得试验”；真实 neutral 结果不够快/不健康则回退，不能用 probe 直接放行驾驶。没有健康路径就停车。路径恢复也不得复活按住的旧输入。这样实现“在安全和切换成本约束下优先最低健康延迟”，不承诺每毫秒的全局最小值，也不为极小收益反复制动。

## 验证矩阵：先隔离故障注入，再协调真实路径

下表是**待执行验收**，不是阶段 2 已通过清单。每项保留 session/authority/path/feedback epoch、native 单调 seq→结果、车端单调接收→锁存、status/lease 进展和原安全门禁；不保存凭据、原始 SDP 或地址。故障注入限隔离 fixture/proxy，现场窗口由主线程安排，不能修改用户防火墙/VPN/路由。

| 组 | 用例 | 必须观察的结果 |
| --- | --- | --- |
| 授权 A/B | 云双向断，DC 操作/结果/视频一直健康 | A 仅到已接受短租约原 deadline，B 在已定义故障检测边界撤回运动；均无旧按键复活，不能运行到五分钟 token 截止 |
| 授权 A/B | socket 假 connected 的静默黑洞；只有单端可达云 | 单调截止独立触发；native 云成功而车未接受不延长；DC 不续权；两端截止取保守共同界 |
| 授权 A/B | 云在截止前/后恢复；CPU 卡顿跨过截止 | 前者 A 且全健康可继续；后者及跨截止不得复活，先停车、fresh authority/neutral/松开重按；执行线程不卡在云 HTTP |
| 撤权/接管 | 分区期间撤权并要求第二驾驶员接管 | 云无重叠 active grant，车端永远一个权威；revoke ACK 只证封存，仍须原安全交接条件；车不可验证时第二人等待 |
| 重放/持久性 | 迟到 renew、重复 grant、时钟倒退/不可信、车/云重启、旧云实例继续发 grant | deadline 不被重置；revoked/expired epoch 不复活；新 boot nonce 拒旧授权；不能证明原 grant 界就不授新权 |
| 原保护 | 租约仍有效但输入停更、视频冻结、结果失联、时钟/CAN失效 | 对应既有保护先触发；不能等租约满，也不延长任何原门限；记录物理证据与软件接受分别报告 |
| 急停择优 | DC 快/WSS 快各一次；媒体 RTT 与真实锁存排序相反 | 两条有界 stop-only 分派；第一条车端有效到达即锁存；择优依据真实急停结果，不能等待慢路 timeout |
| 急停失效 | 主路黑洞、WSS 写阻塞、DC 背压、发送锁争用、ordinary selection 并发 | 备用分派不被主路锁阻塞；普通运动已撤回；共同服务锁存一次；无法确认时 UI 保持未确认 |
| 急停去重 | 双路同 seq、乱序、重复、MAC/内容冲突、旧权威/已复位急停重放 | 首个合法停车，重复只回缓存不 apply/续 watchdog；冲突/旧身份拒绝；网络不能 reset |
| 急停证据 | 软件锁存成功但 CAN 未确认；双路都断 | “已锁存”不冒称物理已停；双断保留未确认并由原车端保护处理，恢复不得解除 latch |
| 反馈矩阵 | 去程 {DC,WSS} × 回程 {DC,WSS} 四组合 | 所有结果精确匹配；四类状态完整、fresh、scope 正确；结果首份消费，不能因重复再计分 |
| 反馈比较 | 去程抖动、回程反向快慢、可信/不可信时钟 | paired return probe 相同前缀；只报告可证明差值，不把混合 RTT当一向时延；无可信时钟绝对值为未知 |
| 反馈切换 | 新/旧 feedback epoch 重叠；旧高 seq；四类状态乱序/丢失 | 新快照按 floor/epoch 生效；旧流不污染 UI watermark；无缺口切换不无故撤输入，真失联仍制动 |
| 健康重排 | WSS 最快、P2P 最快、实际 TURN/UDP/TCP 最快各有真实样本 | 选择最低健康可选择路径；DC 名称不预设胜出；无办法选择的 ICE pair 不入业务候选 |
| 持续重排 | 活动路径仍健康但逐步变慢，备用变快 | 新样本跨改善/稳定/驻留边界后产生建议；自然 neutral 下 fenced trial；真实 accepted neutral 结果才确认 |
| 防抖 | 微小差异、交替快慢、重复旧样本、candidate attempt 变化 | 微小噪声不切；同样本读多次不算稳定；新 attempt 重置 cohort；无并发双路径普通控制 |
| 尾延迟 | 候选平均更快但夹杂秒级结果停顿；样本太少 | 不因平均值快忽略健康失败；p95/median 保持同 cohort，样本不足不称胜出；原 freshness/watchdog 不放宽 |
| 硬失效/恢复 | active 硬断、candidate probe 快但真实结果慢、所有路径断、恢复时按键仍按住 | 故障不等 dwell；候选资格失败保守回退；全断停车；重新健康仍须原松开重按，旧包不过栅栏 |
| 相互作用 | feedback 变路与 control 重排、ICE restart、owner takeover、急停同时发生 | 单轴优化、scope fence 拒旧样本；急停优先；授权不被路径变化延长；无旧 route 高 seq 驱动新 epoch |
| 成本/实测 | 长时运行、限额探测、CPU/本机 HTTP 抖动、TURN TCP HOL | 队列/缓存/带宽有界；记录探测成本和真实 native→车结果/帧呈现；最低路径收益包含 courier 与回退代价 |

建议分四个独立可审查增量实现：①短租约/撤权 fence 与 A/B 故障注入；②stop-only 有界冗余及去重；③独立回程 epoch/测量；④有界后台探测与持续重排。每个增量先默认关闭、Linux 完整车端编译及隔离回归，再由主线程决定现场窗口。当前 PR24 主实施任务可先集成已有阶段 2；本设计不应被解释为已授权现场启用这些新协议。
