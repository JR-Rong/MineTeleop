# session-000059 / 000062：牵引请求与执行反馈诊断

两份现场日志都出现了软件接受牵引、CAN 发出非零扭矩、实际电机扭矩仍为零的情况。session-000062 的驾驶端原生发送全部完成，没有 ACK 停滞或主动重连；因此不能把该次车辆不动归因于 ACK 超时。session-000059 后段另有真实链路超时，其发生时间晚于最初的牵引无响应。

现场 CAN 包含发送成功的 ±320 Nm 请求、EPB 释放请求，以及零普通制动压力请求。电机实际扭矩、电流、转速没有跟随；EHB 压力反馈仍偏高。高压力也出现在此前能够移动的阶段，单凭压力字段不能认定制动是唯一原因。软件发送成功也不等于 VCU 已接收、仲裁或执行。需要供应商提供 VCU 接收扭矩、仲裁结果和牵引禁止原因，才能确认下游原因。

两份日志的页面仍输出旧格式的本地意图响应超时事件，并重复记录参数确认。它们缺少新页面的输入快照字段。可能是旧程序，也可能是更新程序后仍打开旧页面；此前日志不能区分这两种状态。

## 新增记录

车端 `vcu-can.jsonl` 的 `session_start` 记录 `diagnostics_revision=traction-diagnostics-v1`、底盘源码指纹及诊断门限。源码指纹覆盖底盘桥、VCU 解码器和诊断辅助代码；它不是安装包或二进制哈希。

`traction_diagnostics` 将以下信息放在同一条记录中：

- 输入代次、参数修订号、目标速度、纵向输入、PID 输出、控制周期。
- 实际参与本次 PID 判断的阻断条件，包括参数未生效、VCU 未就绪、驻车、挡位、过期反馈和安全锁存；记录驻车释放判定、空闲驻车及反馈新鲜度。
- 最终 CAN 批次的发送成功状态、逐电机扭矩/模式、普通制动压力及 EPB 请求。`cycle` 可关联原有 `can_tx_batch`。
- 同时刻已接收的 CAN 反馈：电机扭矩、电流、转速/质量、逆变器状态和故障等级；EHB 压力、故障等级/代码；VCU、挡位和 EPB 状态，以及反馈年龄。

`gate_sample=before_controller_tick` 表明门禁采样点在 PID 计算阶段，`transmit_state` 是最终 CAN 批次对应的状态。状态机在该周期内推进时，两者可能不同。`feedback_sample=latest_rx_not_tx_ack` 明确反馈来自此前接收帧，并不是对本批次的执行确认。

当某电机实际发送的扭矩幅值至少 10 Nm，而有效、来自 CAN socket 的扭矩反馈幅值不超过 2 Nm，持续观察至少 1000 ms 时，记录 `observation=nonzero_tx_zero_torque_feedback`、电机位图和持续时间。它只是诊断，不触发任何控制动作。

失去 Ready、发送失败、请求撤回、方向改变、反馈无效/过期或采样间隔超过 500 ms，均重新起算。兼容反馈 ABI 没有实际扭矩字段，它合成的零扭矩不用于该观察。观察结束记录 `observation_ended`，而非宣称故障已恢复。每类状态变化最多每秒记录一次，稳定状态每五秒重复；门禁与响应观察各自限频。

驾驶端每条页面事件带 `page_source_sha256`、`diagnostics_revision` 和 `ui_instance_id`，页面加载时记录 `driver_page_loaded`。原生服务落盘时另附 `runtime_console_source_sha256` 和 `runtime_diagnostics_revision`。同一程序生成的页面与原生来源应匹配；旧页面字段缺失或指纹不同，可帮助区分旧页面与当前程序。浏览器上报值是诊断信息，不参与授权或安全判断。

## 现场更新与判读

更新车端才能获得 CAN 牵引诊断，更新驾驶端并重新启动程序、重新打开页面才能获得页面来源标识。云端无需为这轮诊断更新。

| 日志结果 | 可得结论 |
| --- | --- |
| 输入有牵引，阻断条件非空，最终发送扭矩为零 | 检查对应软件门禁及其反馈年龄；页面“就绪”不能替代这些条件 |
| 门禁通过但 PID/最终扭矩为零 | 对照目标/实际速度、PID 输出、扭矩上限和最终 CAN 状态 |
| 非零扭矩发送成功，真实反馈持续为零 | 牵引请求已到本机 CAN socket；继续查 VCU 接收/仲裁、电机及制动条件 |
| 反馈过期或发送失败 | 不把历史零反馈当成执行无响应；对照 CAN 故障和原有安全停车来源 |

原始 `can_rx`、`can_tx_batch` 和既有停车来源继续保留。200/300/800 ms 门限、原生意图租约、首次握手、驻车释放反馈、参数门禁和安全锁存不变。诊断验证不代替机械制动、VCU 仲裁或实车验收。

## 回归覆盖

硬件无关的生产底盘桥夹具覆盖合成零反馈、真实非零 TX/零 RX 持续一秒、扭矩反馈恢复、限频和诊断期间持续输出牵引；VCU 测试覆盖最终驻车门禁后的 CAN 输出、正反方向、失效/过期反馈、发送失败和采样断档。DBC 向量覆盖电机电流/逆变器/故障及双通道 EHB 故障解码。

页面测试覆盖来源字段不覆盖原有输入诊断、原生服务保留旧页面指纹并追加自身标识。实际构建页面使用本地模拟 API 验证来源事件、延迟本地响应仍保留按住输入、急停仍清零并锁存；没有连接现场车辆。
