# PR26 browser directional mock soak, 2026-11-14

This is **local link-only mock evidence**, not independent WAN/5G, real-vehicle, physical steering, or end-to-end video-latency acceptance. The user had authorized the Mac/Orin shared-network setup as partial validation. The original Mac network-sharing bridge was absent, so the existing management cable used temporary link-local IPv4 addresses. No TURN or VPN configuration was changed. The temporary Orin address was removed and test credentials were deleted afterwards.

## Artifact and safeguards

- Tested PR26 product source: `a0aea6a6107eafd6da62c07d86de72523af1a213`, based on `rjr/cx/orin-isx031-cpu`. Orin binary SHA-256: `544699c324f5e6b4c49df5e420d7c94a0d4968c57954592ee62099d80c889620`. The Mac controller was the `88b1bbc` artifact; its product runtime is unchanged by the subsequent tested commits.
- Vehicle identity `test_bench_pr26`; adapter `mock`; Orin CAN interface `down`; field maximum speed, session target speed and session maximum motor torque all zero. The session maximum steering angle was explicitly set to **5 degrees** and acknowledged by the vehicle, so the test exercised nonzero steering in the mock without commanding a real CAN interface. No safety thresholds were relaxed; the clock uncertainty limit was 25 ms. Both physical ISX031 cameras supplied video.
- Browser keyboard input was injected with Playwright, using the ordinary page input handlers. Every two-second scenario checked the held keys and, after settling, correlated the accepted DataChannel result with the effective intent. Forward/reverse scenarios checked D/R respectively; left/right scenarios checked the sign of both the effective steering command and mock steering feedback; brake checked a positive effective brake. The hard profile, two fresh video lanes, focus, clock, path and vehicle safety state were checked throughout.

## Result

The successful run covered `2026-11-14T13:51:25.428Z` through `2026-11-14T14:22:11.998Z`, a **1,846.570-second** sample window. First key-down through last key-up covered **1,847.074 seconds**. All 76 cycles of forward, reverse, left, right, forward-left, forward-right, reverse-left, reverse-right and brake completed. There were 2,736 safety/path samples: 304 per scenario. The trace contains 228 key-down and 228 key-up events for each of W, A, S and D, plus 76 down/up events for Space.

- All samples showed `CONTROL_ACTIVE`, stop sequence 0, two ready video lanes, a trusted clock with sampled uncertainty at most 10 ms, and a qualified P2P DataChannel for commands. The selected UDP pair had the expected local link endpoints and stayed nominated, writable and connected; its reported state was `succeeded` in 2,732 samples and `in-progress` in four.
- In the same timestamp window, the vehicle `receive_apply` trace contained **35,633 accepted DataChannel commands** and no rejected `receive_apply` entries. There were **8,882** accepted commands with requested and applied normalized steering approximately `-0.167` and **8,874** approximately `+0.167`; all accepted requests had zero throttle. Accepted commands included D and R with straight, left and right steering, as well as 2,954 brake requests. There were no vehicle braking-wait or camera-failure events within the window.
- The browser's sampled dispatch-to-vehicle-result-received latency was p50 **15 ms**, p95 **28 ms**, p99 **30 ms**, maximum **36 ms**, based on 2,736 samples of the latest result. This is not a complete per-command distribution, physical execution latency, or camera-to-display latency. Feedback was sampled on DC 1,556 times and WSS 1,180 times; commands stayed on DC.
