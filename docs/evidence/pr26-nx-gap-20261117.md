## Corrected diagnostic coverage

The Linux metadata recorder previously bound AF_PACKET to ETH_P_IPV6. On the
NX this observed inbound DTLS/RTCP but no outgoing media. The outgoing tap in
Linux uses the all-protocol packet-tap list; the recorder now uses ETH_P_ALL
while its existing parser still rejects non-IPv6 traffic and every endpoint
except the exact configured pair. See the primary
[Linux packet-socket documentation](https://www.man7.org/linux/man-pages/man7/packet.7.html)
and [kernel transmit tap implementation](https://github.com/torvalds/linux/blob/master/net/core/dev.c).
This repairs missing evidence, not the network gap itself.

Optional `--include-rtp` adds RTP sequence/timestamp/SSRC, RTCP type and DSCP
metadata. It never saves media or command payloads. Default DTLS records retain
their existing shape; RTP remains opt-in. Endpoint, direction, truncated header,
CSRC, non-IPv6, RTP/RTCP opt-in and DTLS timestamp tests passed with
`python3 scripts/test/ipv6_dtls_metadata_capture.test.py`.

A21 began with an inbound-only private recorder. A replacement using ETH_P_ALL
was started about six minutes into the scored window, verified for inbound and
outbound DTLS plus outbound RTP, then the original recorder was stopped. Both
receipts are retained. The first part has no kernel egress coverage. The private
RTP diagnostic schema and 70-minute limit differ from the default repository
tool; capture coverage must be audited explicitly. Software egress timestamps
are before physical radio delivery and must not be called physical NIC sends.

## A50 page-scope probe and the clock-jitter fix

A temporary probe build (commit `a07a702`, Windows controller SHA256
`844103ced0ff254f666516da5f2191c1f09231e6777cb21422c78b8afd1357c7`) counted
every page snapshot publication and every worker scope read on the same
bench. The 300 s window completed with 13 cycles and one held-input recovery,
but the counters exposed a systematic defect: of 180,800 worker scope reads,
3,168 (1.75%, about 9 per second) were rejected while the page had published
33,500 snapshots with zero publication failures, and the largest accepted age
was 0 ms. Every one of those rejections cancelled the in-flight
`/api/control-transport/bridge` request and dropped that cycle's command.

The rejections came from the ordering check `epochNow() < snapshot.published`:
the page and the worker each keep their own performance clock, so a snapshot
published a few milliseconds ahead of the worker clock read as an expired
page. A49's 3,016 courier cancellations have the same signature and rate.

`762b690` keeps the 200 ms expiry unchanged, rejects only a snapshot more
than 1 s ahead of the worker clock, and treats ordinary millisecond ordering
jitter as live. The node regression keeps the 200/201 ms cases and adds 1, 5
and 50 ms future skew as valid. On that commit all three workflows passed:
Build and release (darwin arm64, linux x64, Windows x64 and arm64, Cloud and
Vehicle Ubuntu), Offline regressions and the Windows native receiver bench.

The fix removes the steady-state command holes; it does not by itself
guarantee the 60-minute criterion, because a page that stops publishing for
longer than 200 ms still blocks the courier by design. A51 (3600 s window,
fresh scoped credentials, controller SHA256
`1282402ce3641a61224fe757f53d886ee4110c91cb39208248bb2706eb72656c`) is staged
for that acceptance run and is blocked on the Windows bench host being
powered on.

   while `RTCDataChannel.bufferedAmount > 0`, `/api/control-transport/bridge`
   still handed each latest DC frame to the worker (`lastSeen` advanced), and
   the worker dropped it with `channel_buffer_not_empty`. `0884d8b` reports

   re-polls immediately on `onbufferedamountlow` or a 5 ms drain check (covering

   `ControlTransportSender::on_result` previously treated any `admitted &&
   !rearm` DC receipt—including `transport_command_expired` rejections and
   accepted stragglers with RTT > `kFreshAckMs` (200 ms)—as fresh progress at
   `now`, keeping A57 on DC epoch 2 (`seq=328..344`) past the 800 ms vehicle
   watchdog. `0884d8b` requires `accepted == true`, credits stragglers older
   than `kFreshAckMs` at `sent.started` rather than `now`, and switches to WSS
   immediately inside `on_result` once `now - last_dc_result_ms_ > kStallMs`.
3. **`prepared_input_retired_no_io` wasted a 50 ms sender period**: when an
   input epoch was retired mid-sample (for example on degraded/re-arm),
   `send_native_control_sample` returned without network I/O and waited a full

## Current decision

Windows scan suppression, NX power-saving suppression and the earlier AP trial
on channel 40 all failed to eliminate the wireless delivery stalls. Moving the
Windows station from -72 dBm to -58..-57 dBm on the same 5 GHz AP eliminated
≥ 200 ms UDP probe gaps in the 723 s A55 idle check, while active dual-video +
control runs (A57, A59) still experienced intermittent ~500-585 ms shared-WLAN
stalls (34,518 NX TX retries and 4 TX failures across A59's 60 minutes).

`762b690` removed steady-state page/worker clock-jitter courier cancellations
(0 courier errors across A59's 60 minutes vs. 3,016 in A49), and `0884d8b`
fixed SCTP backpressure frame consumption, late/expired DC stall-clock resets,
and `prepared_input_retired_no_io` period loss. With both fixes in place, A59
completed the full **60-minute** continuous eight-direction + brake mock
acceptance window (**3,611.569 s** wall / **3,611.6685 s** monotonic, 144
groups, 1,296 verified actions, 0 scored hard stops) with unchanged safety
gates, dual `nvv4l2h264enc` hardware encoders, and direct IPv6/UDP media.

The 180-minute soak criterion (last attempted in A46 before `762b690` and
`0884d8b`), independent monitor-mode air capture to separate endpoint firmware
from AP scheduling/contention, WAN/5G cellular acceptance on the Orin NX
target, physical gamepad input, full native-viewer VCU/session-limit parity,
and physical vehicle/screen scan-out remain unverified and are not claimed
