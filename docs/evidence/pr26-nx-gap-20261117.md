## Corrected diagnostic coverage

The Linux metadata recorder previously bound AF_PACKET to ETH_P_IPV6. On the
NX this observed inbound DTLS/RTCP but no outgoing media. The outgoing tap in
Linux uses the all-protocol packet-tap list; the recorder now uses ETH_P_ALL
while its existing parser still rejects non-IPv6 traffic and every endpoint
except the exact configured pair. See the primary
[Linux packet-socket documentation](https://www.man7.org/linux/man-pages/man7/packet.7.html)
and [kernel transmit tap implementation](https://github.com/torvalds/linux/blob/master/net/core/dev.c).
This repairs missing evidence, not the network gap itself.

Optional `--include-rtp` adds RTP sequence/timestamp/SSRC, RTCP type and DSCP
metadata. It never saves media or command payloads. Default DTLS records retain
their existing shape; RTP remains opt-in. Endpoint, direction, truncated header,
CSRC, non-IPv6, RTP/RTCP opt-in and DTLS timestamp tests passed with
`python3 scripts/test/ipv6_dtls_metadata_capture.test.py`.

A21 began with an inbound-only private recorder. A replacement using ETH_P_ALL
was started about six minutes into the scored window, verified for inbound and
outbound DTLS plus outbound RTP, then the original recorder was stopped. Both
receipts are retained. The first part has no kernel egress coverage. The private
RTP diagnostic schema and 70-minute limit differ from the default repository
tool; capture coverage must be audited explicitly. Software egress timestamps
are before physical radio delivery and must not be called physical NIC sends.
