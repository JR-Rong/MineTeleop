# PR24 独立普通反馈运行时检查点

本层基于 `fd63c94`，接入既定的独立反馈 epoch。普通控制仍由 native
分配全局 seq 并单路发送；复用现有 DC、云 WSS、签名和本地字节桥，
没有新增线程、socket、普通命令副本或网络设置。停车专用双路是前一层
已实现的 stop-only 例外。

**实验仍默认关闭。** 必须同时满足原生实验选项、当前车端 offer 的
`native-feedback-transport-v1` 能力，以及车端已接受的短授权。
没有 YAML/CLI/UI 启用入口。600ms 只是本机 fixture，用户尚未批准
生产租期；本文件不是启用或部署批准。

## 独立轴与协议边界

1. 普通命令的签名覆盖 `feedback_request`：独立 epoch/from_epoch、
   回程路径、当前 media attempt、短授权 issuer/authority epoch，
   以及选择和同事件回程探测标记。它不携带新 grant。
2. 车端在原有公共控制锁内，先校验真实身份、原生 MAC、短授权和普通
   命令准入，再对反馈选择执行相邻 epoch CAS。重复选择不改变状态
   floor。选择不调用执行机构、不刷新安全 watchdog，也不续任何租约。
   普通命令与反馈的 epoch 互不替代。
3. 车端签名结果回显精确请求、实际反馈状态及实际命令接收载体。
   native 必须命中本机实际发送记录的 seq、intent、命令传输戳、
   反馈请求和命令接收载体，才可更新结果健康度或状态。
4. 状态只走选定反馈路径；同一普通命令可请求一个有界的成对结果探测，
   将**同一份不可变车端结果**经两种回程送回。最多一个成对探测在途，
   最多保留128条实际发送记录。它不是重复发送控制命令。
5. native 对该事件的首次有效结果只推进一次普通 ACK/结果进展；第二路
   只形成回程比较，重复包不刷新健康度。当前 epoch 的探测备份结果
   可以证明真实命令仍有端到端反馈，使反馈回程单向故障可独立回退，
   而不先迫使健康命令路径改变。

## 路径选择与度量

- 只有当前 media attempt 的实际 ICE 分类 `p2p` 享有直连优先。
  DC open 或媒体 RTT 不算控制结果证明；仍需真实 accepted 结果完成
  既有连续三次健康资格。健康 P2P 不因 WSS 短时更快而退出。
- TURN/unknown 不标作 P2P。使用同一车端事件、同一前向路径/命令
  epoch 的两路结果比较；有足够健康样本才比较。任一路失效则以健康
  可用回程为保底，不从不同前向样本推导“单向延迟”。
- 回程异常沿用既有结果新鲜度200ms、连续三次异常、停滞500ms，以及
  已有 recovery timeout 的重试等待。200ms 也用于已在途探测过期；
  没有新云失联停车门禁，未修改输入、时钟、视频、CAN、授权或控制
  watchdog 的阈值。
- authority、media attempt、命令路径/epoch 改变即隔离成新的比较组，
  旧记录不能填充新健康窗口。反馈确认切换也清空普通路径比较统计，
  避免混入另一回程的数据；它不单独清除驾驶输入。
- 状态里的 paired round-trip mean 包含 native/浏览器调度、前向、
  车端处理及回程；两个值来自同一事件，差值才可比较相对回程。
  不是单向延迟，也不是物理执行时间；历史均值需结合 trace 时效使用。
  `feedback_transport_selected` 和现有结果 trace 记录独立反馈 epoch、
  实际命令接收载体与实际结果回程。

## 旧包、乱序及 UI 水位

- 状态包带签名反馈 epoch 和车辆选择时的 `status_floor`。native
  在推进全局状态序号之前验证 MAC、当前身份/attempt/authority、
  feedback epoch、floor 和选定回程。旧 epoch 的巨大 seq 也不能
  推进新水位。
- 四种状态先保持最多各一个快照，再按实际 publication seq 排序输出。
  一个 HTTP 请求期间到达的较新快照不会被旧请求完成清除。
  云缓存和云 socket 的发送水位也先比较反馈 epoch，再比较 seq。
- 新模式下旧云 ACK 中不带反馈 epoch/MAC 的摘要不再更新车端反馈
  水位或触发输入恢复；云入口 ACK 仍只是其原有入口证据。车端真实
  结果通过签名结果分支处理。
- 浏览器只将新模式 DC 状态转交 native 验证，不直接将其当作车辆
  证据。经 native 返回的状态还须通过当前反馈戳检查，之后才进入
  原有 UI 全局水位和 CAN/VCU/换挡等 reducer。
- 反馈切换时车端可重新发布三个当前状态快照，保留原 CAN/证据时间。
  `control_command_rejected` 是事件通知，不因路径切换重新发布，
  防止把旧拒绝重当成新事件而清除输入。新鲜 CAN、实际执行及恢复
  资格仍由原有逻辑判断。

## 本机验收证据

- 原生/云运行库与相关测试目标在 macOS 编译通过。
- 离线 CTest **7/7**：反馈生产类7组（真实 MAC、四种前向/回程组合、
  P2P优先、独立回退、丢失选择的精确 CAS 对账、旧 epoch/乱序/重复/
  固定容量）；提取的实际车端反馈发布方法；原停车、短授权、普通传输、
  JS和ICE回归。JS courier 共12项，原有页面控制逻辑98项通过。
- 实际车端 `send_control_status_locked` 方法从当前源文件提取并编译，
  运行真实反馈 fence、真实 MAC 和假 Gst 发送器，验证四种路径组合、
  四类快照、旧身份过滤和原证据时间保留。不是 GStreamer ABI/网络证明。
- 实际 localhost native/cloud 集成使用真实 HTTP/WSS、原生生产器、
  MAC 和共同控制服务，DC 字节传输模拟：DC命令配WSS反馈，恢复后
  反馈切到P2P，再单向丢DC回程使反馈回退WSS，普通命令 epoch/path
  保持不变。旧 epoch 的 UINT64_MAX 状态经过实际云缓存/socket，
  新 epoch 的较小有效状态仍可到达；重复/篡改和乱序四类批次也覆盖。
- 同一集成目标回归：先卡普通 WSS 和普通桥接，之后才首次急停，
  原生停车锁存/DC发布及软件回执仍不等待该阻塞结束；原云短断流和
  车端独立授权到期停车测试仍在。

日志位于委派任务根目录的 `feedback-*-final.log`。具体命令、提交及
日志散列另存交接 JSON，不将本机成功推广为真实 P2P/NAT/执行机构证明。
