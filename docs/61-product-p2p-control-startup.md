# 正常启动的 P2P 控制优先与云端回退

本次接入以 PR24 的 `0276e93` 为基线。正常驾驶端默认 `control.transport_mode: p2p_preferred`，两个 C++ 启动入口都支持 `--control-transport p2p_preferred|cloud_only`。`cloud_only` 仍协商原生传输协议，利用同一套 WSS epoch、车端结果和状态回传；它不试发 DC 普通控制。实验性 TURN 对比和短时离线授权没有 YAML/CLI 产品入口，离线授权仍关闭。

## 已核实的接入缺口

此前正常 YAML 和两个启动程序都未设置实验开关，驾驶端因而不申请会话 MAC key、不协商控制传输能力，页面也不轮询原生字节桥。车端已有接收和鉴权代码并不等于正常产品已走直连。

此前页面桥使用视频统计中的候选对。现在每次桥请求及发包前读取 `peer.sctp.transport.iceTransport.getSelectedCandidatePair()`，要求 SCTP、DTLS 和 ICE 都已连接，两端候选都为 host/srflx/prflx 才报告 P2P。任一端 relay 报告 `turn_unknown`，API 不支持、没有候选对、状态断开或候选类型缺失都报告 unknown 并停留 WSS。这里不猜 TURN 的承载协议、不输出候选地址，也不用媒体 RTT 判断控制健康。API 语义见 [W3C RTCIceTransport](https://www.w3.org/TR/webrtc/#dom-rtcicetransport-getselectedcandidatepair)。

此前车端必须等 DC 打开才启动公共安全服务，首次 WSS epoch 也没有启动路径。现在先以中性命令完成 WSS 选择；车端在已认证原生 WSS 在线、协议能力匹配、常规租约有效时可启动安全服务并经 WSS 回传适配器状态。控制启用、关键摄像头、会话停止、故障抑制和恢复锁检查仍在。启动服务不会安装控制参数或自动握手。

## 实际调用路径与边界

| 链路 | 正常路径、健康依据和回退 |
| --- | --- |
| 控制面 | 登录、车辆发现、审批、会话/租约、SDP/ICE 信令仍经认证云端；参数与 VCU 管理在传输协商后经认证云端。 |
| 视频 | 摄像头→GStreamer→WebRTC ICE→浏览器。保留 `all` 的 host/srflx/TURN 候选和既有 ICE 选择，不强制 relay 或修改网络。控制的 P2P 识别不宣称媒体实际已直连。 |
| 普通控制 | 页面输入→本机原生意图租约→原生定时生产者/MAC→单一 WSS 或 DC 路径→车端共享 epoch/seq fence→公共安全服务。页面只搬运原生签名字节；不生产控制命令或并发双发。 |
| 控制结果 | 车端签名结果→DC 字节桥或既有云 WSS 回传→原生按实际发送的 seq/intent/epoch 精确关联。资格确认使用该往返，包含页面调度和实际回包等待；云入队 ACK、ICE RTT 均不能代替它。 |
| 状态反馈 | 本产品阶段沿用所选控制路径的 DC/WSS 状态回传，WSS 可独立完成启动；独立反馈路径的短授权实验仍关闭。结果的既有 DC/WSS 回传不产生第二条普通控制发送。 |
| 急停 | 保留当前常规云 WSS 急停和公共接收器锁存语义。已存在的短授权 DC stop-only 实验不因本次产品开关而启用；本次不宣称急停离线可用或物理执行已确认。 |

三端握手为：正常驾驶端请求协议能力及会话临时 key→认证车端发现同一会话 key 并在 offer 中声明能力→云原生 WSS 升级确认协议→中性 WSS epoch→页面报告当前 SCTP 候选→原生试选 P2P。缺少任一能力时沿用 WSS，key 不进入本地 UI connect/status 或日志。

## 选择与安全门限

本轮产品策略是**健康 P2P 默认优先、云端备份**，不承诺 P2P 的数值 RTT 永远小于 WSS。P2P 必须取得三个真实、接受的中性控制结果，每个往返不超过既有 200 ms；选择和资格确认期间禁止运动。TURN/unknown 产品模式不参加 DC 普通控制试选。实验性 relay 比较保留原有实际结果比较，仅供 C++ 测试。

路径失效、桥作用域/页面/ICE attempt 变化、桥租约过期、缺少结果或既有 ACK 互锁触发时，原生先撤回运动，再用递增 epoch 中性选择 WSS。旧路径和旧 epoch 不能重标后回放。恢复 P2P 仍遵守现有重试滞回（无车端覆盖时为 5000 ms），选择与恢复都会触发原生及页面清零，旧按住的输入必须先松开再重按。

本次没有修改 200 ms 输入/命令新鲜度、100 ms 桥发布寿命、500 ms ACK 停滞及三次异常、300 ms 共同健康恢复窗口、时钟门限或车辆失联停车门限。常规控制仍要求云端权威及常规租约；已观察到云 WSS 断开或租约失效就拒绝 DC 普通控制。没有选用测试中的 600 ms 作为生产离线授权时长。未被检测到的传输失效仍受既有云会话发现和常规租约边界约束，本次不新增离线续期。

## 离线验收

`mine-teleop-product-direct-integration-tests` 使用正常 YAML、真实原生生产者、真实云 HTTP/WSS、真实 MAC/fence 和公共安全服务；只模拟 DC 字节搬运，不涉及 WebRTC、CAN 或车辆。

- 无 DC 完成初始 WSS epoch，模式默认 P2P 优先，实验和离线授权关闭；`cloud_only` 即使报告 P2P 也不试发 DC。
- TURN/unknown 不能进入产品 DC 控制；健康 P2P→未知路径 WSS→恢复 P2P 使用递增 epoch，旧命令不能重放。
- 跨切换持续刷新旧油门请求不能恢复运动；实际中性松开之后才允许完成资格确认。
- 云端权威无效、常规租约过期的直连命令被拒绝，签名 key 不出现在状态中。
- 实际车端启动方法在未认证、能力缺失、租约过期、摄像头未就绪、故障抑制、会话停止或控制禁用时均不打开 Mock 适配器。
- 实际车端状态发布方法可在无 DC 且云权威有效时回传启动状态，失效后不以此启动反馈。
- JS 验证实际 SCTP 候选分类，以及 HTTP 桥等待期间 P2P→TURN 变化时丢弃字节、恢复后不回放；页面管理与安全退出继续执行生产方法。

验收还需精确提交的 Linux 车端/GStreamer 编译、各驾驶平台构建和 CI 回归。现场 P2P 建连、真实命令延迟、回退与恢复必须由主线程协调的跨机测试确认。本轮没有部署、台架/SSH、Mac UI、云服务重启或防火墙/VPN/路由变更。

既有现场证据仅证明 relay→relay TURN/TCP 被选中，以及所测云 STUN UDP3478 超时。host/srflx 检查失败的具体网络原因仍未闭环，不能据此断言全部 UDP 被阻断，本次也不宣称已恢复真实跨机 P2P。后续最小探测应先关联同一 ICE attempt 的两端候选/检查日志，再按获协调的单一端点和有限次数验证 STUN/UDP，不修改网络设置。
